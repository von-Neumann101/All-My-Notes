## 数组的定义
`tracegen.c` 中的定义：
```c
static int A[256][256];
static int B[256][256];
```
所以 `A`, `B` 对应位置的相差 $256\times 256\times 4=2^{18}\text{ bytes}$
## 常识
二维数组是**按行连续排列的**
# 32 x 32
需要分多少块呢？32 x 32 中一整行为 32 x 4=128 字节，所以一行占 128/32=4 个 cache block。而一个 cache block 可以放 8 个 int 数据，所以分 8 x 8
接下来 `B[v][u] = A[u][v];` 就可以了……吗？
现在看读取 A，读取第一个元素时，会把后面 8 个放到 cache 中，接下来再把第一个元素写到 B 的第一个位置 `[0][0]` 中。但是，B 和 A 的对应位置隔着 $2^{18}$ 字节。在*圆环*中，这会覆盖数据。也就是说，写入 B 的时候，会把 A 的缓存覆盖。**尤其**是对角线位置的（还有别的位置，但是有点麻烦，不予考虑。只考虑对角即可满分）
所以我们只需要先把 A 存入缓存的元素取到运行时栈或者寄存器里就行
# 64 x 64
## 分析
为什么不能继续 8 x 8 呢？这是因为现在一行是 8 个 cache block，整个缓存一共有 32 个 cache block，所以**前 4 行就会占满** cache。

先看 A，因为 A 是按照行顺序读取的，只要 A 读不超过 4 行就能防止冲突
再看 B：写第一列：
```
B[0][0]
B[1][0]
B[2][0]
B[3][0]
B[4][0]
B[5][0]
B[6][0]
B[7][0]
```
后面的四行会驱逐前面的四行，那么写到 B 的下一列（A 的下一行）的时候，又需要重新读取
```
B[0][1]
B[1][1]
```
理论上 `B[0][1]` 和刚才的 `B[0][0]` 在同一个 cache block。但是却被 `B[4][0]` 驱逐了。

那么使得 A 不冲突的最小单元是 4 x 8，使得 B 不冲突的最小单元是 4 x 4（这里是为了维护 2 的幂次）
## 解 1
```c
int i, j, k, h;
int a0, a1, a2, a3;

for (i = 0; i < 64; i += 4) {
    for (j = 0; j < 64; j += 8) {
        // 一个 4×8 块，再拆成两个 4×4 
        for (h = 0; h < 2; h++) {
            int col = j + 4 * h;
            // 当前处理 A[i:i+4][col:col+4]
            for (k = i; k < i + 4; k++) {
                a0 = A[k][col];
                a1 = A[k][col + 1];
                a2 = A[k][col + 2];
                a3 = A[k][col + 3];
                B[col][k] = a0;
                B[col + 1][k] = a1;
                B[col + 2][k] = a2;
                B[col + 3][k] = a3;
            }
        }
    }
}
```
