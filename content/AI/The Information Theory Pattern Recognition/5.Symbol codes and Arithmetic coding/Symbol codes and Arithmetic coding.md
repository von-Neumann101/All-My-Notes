# Better Symbol Codes
上一节我们知道了Huffman编码，但是这真的实现了最优的压缩吗？
之前的Bent Coin问题中，我们分别给正/反面编码为0/1（满足Huffman编码）
这样我们得到了期望码长为1——然而$H\approx 0.08 \text{btis}$，约期望码长的$\dfrac1{12}$
## 猜字游戏
要求猜出下面一句（给定了52个候选字+1个特殊空格字符）：
```text
像素方块的硬核才是王道 你的卡通画风根本没技巧
```
**事实**：
- 我们的预测分布会随着上下文变化而变化（在预测完“像素”后，第三个字为“方”的概率更高）
- 与上下文相关的预测也会随着对文本风格的理解而产生变化（如果你知道了这是歌词，预测押韵的概率也会增高）
- 一般，预测的分布是确定的

比如对于某一位的预测：
```
道 0.990
像 0.002
硬 0.002
块 0.002
的 0.002
卡 0.002
```
如果使用Symbol Codes（Huffman编码），显然$L>1$，然而由于我们的判断相当确定，所以**信息熵应当非常小**——$H<<1$，所以如果使用Symbol Codes是无法达到香农给定的下限的

如果现在有你的克隆体，会和你做出完全相同的预测，那么只需要让你的克隆体猜测每一个字，并记录猜测的次数。你获得了每个字猜测次数的记录，接下来你只需要按照记录的次数来猜测字，就能得到完整的句子了
# Arithmetic coding
3个组件：
- Bent coin（$P(a)=0.01,P(b)=0.99$未知）
- Unknown bent coin（$P(a),P(b)$未知）
- 可复制的预言机：给定任何的上下文，其会提供下一个字符的概率。并且复制的每个预言机对于同一个上下文都有相同的预测
## Arithmetic coding
可以将**二进制字母表中的任何传输**视为**在实数轴上定义一个区间**
把下标的上边界看为0，下边界看为1：
![[Pasted image 20260910104121.png|443]]
比如：
```
01  -> [0.25, 0.5]
100 -> [0.5, 0.625]
```

这里之所以能给出一个区间还有一种重要的解释：
```
101 -> 0.101......
```
代表了所有二进制小数位前三位为101的所有小数
```
0.10111... < 0.101 < 0.10100...
```

以Bent coin来举例：
![[ChatGPT Image 2026年9月10日 15_25_19.png|686]]

由于我们的预言机有两台，预言机给出的概率是对于两者而言是已知的，也就是下面的蓝粉区间是已知的。所以我们可以用**任意一个在这个区间里的二进制串来代表某个结果**
注意，每个区间长度恰好是结果的联合概率的大小

**定理1**：编码出的二进制串的长度满足如下不等式：
$$
l(x_1,x_2,...,x_N)\le \log_2\frac1{p(x_1,x_2,...,x_N)}+2
$$
也就是说，算术编码给出的长度的上界只比Shannon给出的上界大2（注意，这是对整个文本来说的）

**定理2**：需要计算$N\times I$个条件概率，就可以完成编码-解码

注意，我们并没有要求源字母表和传输字母表的形式——也就是说，只要编码能落在结果的区间就可以
