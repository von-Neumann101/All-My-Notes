# MEG
MEG是**每个homesever维护**的一个记录event历史的DAG
![[Pasted image 20260515095804.png|563]]
## 原理
使用“因果关系”来形成一个DAG，在用户发消息的时候，根据当前homesever的MEG的 forward extremities（也就是末端没有连接节点的节点）把新的event连接到他们
例如，当前有两个forward extremities，我新增的一个D，那么D的prev就是B和C，我们建立这样的连接：
```
     B ─┐
    /   │
A       ├→ D
    \   │
     C ─┘
```
### 并发
由于每个homesever维护自己的MEG，然后再同步，由于网络延时等问题，最终可能会因为同步不及时导致**并发**
比如，每个homesever开始同步MEG的时候，发现各自的新event都连在了A节点上，这就会导致并行连接
```
    B
   /
A
   \
    C
```

# JavaScript
在openclaw里，JavaScript处在比Python之类语言更高的抽象层级（事件层、协议层、编排层、Gateway 核心层）
作为一个**事件调度语言**，其处理的是
```
“发生了什么事件？”
“这个事件属于哪个 session？”
“它来自哪个 channel / node / webhook？”
“是否有权限执行？”
“应该调用哪个 plugin / skill / MCP server？”
“结果应该返回给谁？”
```
在Openclaw里，其作为Gateway的基础
1. 事件调度
JS不会自己处理具体任务，而是把系统行为组织起来。例如：
```
收到一个 HTTP 请求
→ JavaScript 解析请求
→ 检查权限
→ 判断要调用哪个 tool / plugin / MCP server
→ 发起调用
→ 等待结果
→ 把结果返回给前端或用户
```
2. 管理网络通信
这与他“事件调度”的功能是一样的
```
协议入口
连接管理
请求解析
响应生成
WebSocket 双向通信
```
3.  非阻塞 I/O
# Node.js
JavaScript 原本**主要跑在浏览器**里，**Node.js** 让 JavaScript 可以跑在**服务器、本地程序、命令行工具、Gateway 后端**里
```
JavaScript = 编程语言  
V8 Engine = 执行 JavaScript 的引擎  
Node.js = 把 V8 包装起来，并提供文件、网络、进程等后端能力的运行环境
```
综合来说，Node.js可以让JS可以处理I/O、网络、进程等东西
```
用户 / 前端 / 外部系统
↓
HTTP / WebSocket 请求
↓
Node.js Gateway 接收
↓
转成事件
↓
检查权限、上下文、会话
↓
调用插件、Skill、MCP Server、模型或外部工具
↓
返回结果
```

# MCP(Model Context Protocol)
MCP 可以让 OpenClaw 调用 Gateway 核心之外的外部工具/服务
假设微信不是OpenClaw Gateway的内置能力，我们有如下方式接入
```
1. Plugin
如果微信接口需要深度访问 Gateway 内部数据，可能做成 Plugin。
2. Channel
如果微信是“用户消息入口”，比如用户从微信给 Agent 发消息，它更像 Channel。
3. MCP Server
如果微信只是一个外部工具能力，比如“发送微信消息”“读取微信联系人”“获取某个聊天窗口内容”，那它可以做成 MCP Server。
4. Node / Bridge
如果需要适配微信客户端、网页端、自动化脚本、Windows API、AHK 等，也可能先写一个外部 bridge，再由 Gateway 调用。
```
## Node vs MCP
MCP 更像“标准化工具调用接口”
Node 更像“长期运行的外部系统桥接器 / 接入适配器”
MCP的抽象更像——`call_tool(name, args) → result`
Node 的抽象更像一个 **connector / bridge / adapter**
以微信举例：
如果只是让Agent可以发微信，用MCP
如果要让微信成为 OpenClaw 的入口，用Node/Channel
# Hooks
